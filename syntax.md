# Расширения языка

## Типы

`int` (32 бита), `int64`, `uint64` (беззнаковый 64-битный), `float`, `char`, `byte` (беззнаковый 8-битный), `string`, `bool`, `void`, а также составные: `[]T` (массив), `*T` (указатель), имя структуры или интерфейса.

```pgt
var* a = 1                  // int
var* b int64 = 3000000000
var* c = 'x'                // char
var* d + {float} = 2        // явный тип
var* e int                  // нулевое значение
```

Преобразования: `int(x)`, `int64(x)`, `uint64(x)`, `float(x)`, `char(x)`, `byte(x)`, `bool(x)`, `string(x)`.

`uint64` принимает литералы до `18446744073709551615`, поддерживает беззнаковые деление, остаток, сравнения и сдвиг вправо, `str(x)` и `fmt` печатают полное беззнаковое значение. Смешивать `int64` и `uint64` без явного преобразования нельзя (ошибка компиляции), унарный минус и отрицательный литерал для `uint64` запрещены. `uint64` можно использовать как ключ `map`, в `extern` он передаётся как `uint64_t`. Литерал, не помещающийся в `int64`, для `int64` — ошибка.

Целые литералы можно писать в шестнадцатеричном и двоичном виде: `0xFF`, `0b1010`. Комментарии: `// до конца строки` и `/* блочные */`.

## Константы и глобальные переменные

```pgt
const PI = 3.14
const (
    Answer = 42
    Name = "PGT"
    Big int64 = 9000000000
)

var* counter = 0
var* table = buildTable()   // любое выражение, в том числе вызов функции
```

Константы и глобальные переменные объявляются только на верхнем уровне файла. Они инициализируются до вызова `main`: сначала в импортированных пакетах, затем в порядке объявления. Константу нельзя изменить: `PI = 3` — ошибка компиляции. Из другого пакета они доступны как `math.Pi` (если имя с большой буквы).

## Операторы

Арифметика `+ - * / %`, сравнение `== != < > <= >=`, логика `&& || !` (с короткой оценкой), побитовые `& | ^ << >> ~`, составное присваивание `+= -= *= /= %=`, `++` и `--` для любых изменяемых значений (`arr[i]++`, `p.X--`, `*p++`).

Строки склеиваются через `+`, в том числе с числами, символами и bool: `"n=" + 5`. Строки сравниваются операторами `== != < > <= >=` (лексикографически).

Приоритеты (от слабого к сильному), как в Go:

| Уровень | Операторы |
|---|---|
| 1 | `\|\|` |
| 2 | `&&` |
| 3 | `== != < > <= >=` |
| 4 | `+ - \| ^` |
| 5 | `* / % << >> &` |
| 6 | унарные `- ! ~ * &` |

Поэтому `x & 1 == 1` означает `(x & 1) == 1`.

Целочисленное деление на ноль завершает программу с `panic: integer divide by zero`.

## Перенос строк

Точка с запятой не нужна: оператор заканчивается вместе со строкой. Если выражение продолжается на следующей строке, оставьте оператор в конце строки:

```pgt
var* total = a +
    b +
    c
```

Строка, начинающаяся с `*`, `&`, `-`, `(` или `[`, — это новый оператор, а не продолжение предыдущего (`var* p = &x` и следующей строкой `*p = 5` — два разных оператора).

## Условия и циклы

```pgt
if x < 0 {
} else if x == 0 {
} else {
}

for var* i = 0; i < 10; i++ { }
for i in 0..10 { }          // 0..9
for x in arr { }
for i, x in arr { }
for ch in "text" { }
for cond { }
for { break }

switch x {
    case 1, 2 { }
    case 3 { }
    default { }
}
```

`switch` без значения проверяет условия по порядку:

```pgt
#use "fmt"

switch {
    case x < 0 { fmt.Println("negative") }
    case x == 0 { fmt.Println("zero") }
    default { fmt.Println("positive") }
}
```

`case` сравнивает значения любых типов, у которых есть `==` (числа, символы, строки, bool). Выполняется первая подходящая ветка; перехода в следующую нет.

`break` и `continue` работают во всех циклах, `break` — и в `switch`.

## Массивы

```pgt
#use "fmt"

var* arr = [1, 2, 3]
arr[0] = 10
arr = append(arr, 4, 5)
fmt.Println(len(arr), arr)
var* grid = make([]int, 5)
var* names + {[]string} = []
```

Выход за границы массива завершает программу с сообщением `panic: index out of range`.

Срезы, как в Go: `a[i:j]`, `a[i:]`, `a[:j]`, `a[:]`. Для массива результат разделяет данные с исходным (длина `j-i`, ёмкость `cap(a)-i`; `j` может доходить до ёмкости), поэтому запись через срез видна в исходном массиве. Срез держит исходный блок живым, даже если сам массив уже вышел из области видимости: в заголовке массива `{data, len, cap, base}` поле `base` указывает на начало управляемого блока, и счётчик ссылок считается по нему. `append` к срезу пишет на месте, пока хватает ёмкости, иначе переносит данные в новый блок. `cap(a)` возвращает ёмкость. Для строки `s[i:j]` создаёт новую строку-подстроку по байтам (индексы считаются в байтах UTF-8). Выход за границы: `panic: slice bounds out of range [i:j] with length n` (для массива `with capacity n`).

Массив хранит ссылку на свои данные, как срез в Go: `var* b = a` и передача массива в функцию не копируют элементы, поэтому `b[0] = 1` меняет и `a`. `append` может перенести данные в новую память, поэтому всегда присваивайте результат: `a = append(a, x)`. Массивы можно вкладывать: `[][]int`, `[]Point`, `[]*Node`.

`fmt.Println` печатает массивы и структуры целиком: `[1 2 3]`, `{1 2}`, указатель на структуру — `&{1 2}`, пустой указатель — `<nil>`.

## Структуры и методы

```pgt
#use "fmt"

struct Point {
    X int
    Y int
}

fn (p Point) Sum() int {        // получатель по значению
    return p.X + p.Y
}

fn (p *Point) Move(dx int) {    // получатель по указателю
    p.X += dx
}

var* p = Point{X: 1, Y: 2}
p.Move(5)
fmt.Println(p, p.Sum())
```

## Указатели

```pgt
var* x = 1
var* px = &x
*px = 5
var* q = &Point{X: 1}
var* h = new(Point)
free(h)
```

`nil` — пустой указатель, строка, массив или интерфейс. Разыменование `nil` завершает программу с `panic: nil pointer dereference`.

На локальную переменную можно взять указатель и вернуть его из функции: такие переменные автоматически размещаются в куче.

Методы с получателем по указателю можно вызывать у обычной переменной (`p.Move(5)`), а методы по значению — у указателя (`ptr.Sum()`): адрес берётся и снимается автоматически. Поля доступны через указатель так же: `ptr.X`.

## Интерфейсы

Реализуются неявно, как в Go: достаточно, чтобы у типа были все методы.

```pgt
#use "fmt"

interface Shape {
    Area() float
}

fn describe(s Shape) {
    fmt.Println(s.Area())
}

describe(Rect{W: 2, H: 3})     // методы по значению: подходит и Rect, и *Rect
describe(&Circle{R: 1})        // методы по указателю: подходит только *Circle
```

Переменная-интерфейс без значения равна `nil`; вызов метода у неё завершает программу с паникой. Пустой интерфейс `interface Any {}` принимает значение любого типа. `fmt.Println` печатает значение, лежащее внутри интерфейса. Тип `any` (см. ниже) принимает значение любого типа.

## Функции с типами

```pgt
#use "fmt"

fn add(a int, b int) int {
    return a + b
}

fn greet(name string) {
    fmt.Println("Hello, " + name)
}
```

Параметры без типа считаются `int`. Функция без типа результата возвращает `int`, если в ней есть `return` со значением, иначе ничего.

## Ввод

```pgt
#use "fmt"

fmt.Input("Число: ", &n)        // int, int64, float, char, bool, string (одно слово)
fmt.InputLine("Строка: ", &line)  // строка целиком
fmt.Input("", &p.X)                 // можно читать в поле структуры или элемент массива
```

Если прочитать значение не удалось (конец ввода или не число), переменная не меняется. `bool` принимает `true/false`, `yes/no`, `y/n`, `1/0`. Чтение в `byte`, структуру или массив, а также `InputLine` не в строку завершает программу с паникой.

Остальные функции ввода пакета `fmt`: `Scan(&a, &b)` читает слова через пробелы и возвращает число прочитанных значений, `Scanln(&a, &b)` разбирает остаток текущей строки, `ReadLine()` возвращает следующую строку целиком.

## Вывод

Вывод целиком реализован на PGT в пакете `std/fmt`: компилятор знает только тип `any` и функции рефлексии (см. ниже).

```pgt
#use "fmt"

fmt.Println("a=", 1, " b=", 2.5)      // a=1 b=2.5 — аргументы склеиваются без пробелов
fmt.Print("no newline")
var* s = fmt.Sprintf("%d|%5.2f|%s|%q|%x|%c|%t|%v", 42, 3.14159, "hi", "q", 255, 'z', true, [1, 2])
fmt.Printf("%-5d|%05d|%%\n", 7, 42)
```

Глаголы `Printf`/`Sprintf`: `%v` (как `Println`), `%d`, `%s`, `%f` (точность `%.2f`), `%g`, `%c`, `%t`, `%q`, `%x`, `%X`, `%%`; флаги `-`, `0`, `+` и ширина (`%8.3f`). Неверный глагол или тип дают `%!d(string=s)`, нехватка аргументов — `%!d(MISSING)`, лишние — `%!(EXTRA int=1)`.

`Print`, `Println`, `Sprint`, `Sprintln` не вставляют пробелы между аргументами. Массивы печатаются как `[1 2 3]`, структуры — `{1 2}`, указатель на структуру — `&{1 2}`, `nil` — `<nil>`; значение внутри интерфейса печатается по своему динамическому типу.

## Тип any и вариативные функции

`any` — пустой интерфейс: в него неявно преобразуется значение любого типа (`nil` тоже). `any` хранит пару «данные, описание типа» и учитывается в подсчёте ссылок, как интерфейсы. `a == nil` проверяет, что в `any` ничего нет.

```pgt
var* a any = 5
var* b any = Point{X: 1}
var* c any = nil
```

Последний параметр функции может быть вариативным: `name ...T`. Внутри функции это `[]T`. При вызове лишние аргументы собираются в новый массив, а готовый массив передаётся через `xs...`:

```pgt
fn sum(base int, xs ...int) int {
    var* t = base
    for x in xs { t += x }
    return t
}

sum(1)                 // 1
sum(1, 2, 3)           // 6
var* nums = [4, 5]
sum(0, nums...)        // 9
```

Вариативными могут быть функции и методы, но не `extern fn` и не методы интерфейсов. Как в Go, `[]string` нельзя передать как `...any`: нужен `[]any`.

Над `any` работает пакет `reflect` (`#use "reflect"`), написанный на PGT поверх пакета `unsafe`. Компилятор создаёт описатель типа для каждого типа, преобразуемого в `any`; структура `reflect.Type` в точности повторяет его раскладку (`Kind`, `NumField`, `Name`, `Elem`, `Size`, `Drop`, `Retain`, `Fields`). Значение, лежащее в интерфейсе, при преобразовании в `any` получает динамический тип.

API `reflect`: `TypeOf(a) *Type`, `Kind(a) int`, `TypeName(a) string`, `Int`, `Float`, `Bool`, `String`, `Len`, `Index(a, i) any`, `NumField`, `FieldName(a, i)`, `Field(a, i) any`, `Elem(a) any`, `IsNil`, `Addr`, `SlotIface(a, i)`, `SetInt`, `SetFloat`, `SetBool`, `SetChar`, `SetString` (запись через указатель в `any`). Коды видов: `KindNil` 0, `KindInt` 1, `KindInt64` 2, `KindFloat` 3, `KindChar` 4, `KindByte` 5, `KindBool` 6, `KindString` 7, `KindArray` 8, `KindPointer` 9, `KindStruct` 10, `KindIface` 11, `KindAny` 12. Неподходящий вид — паника `reflect.Int: unsupported value of type string`.

### Пакет unsafe (низкоуровневые примитивы)

`#use "unsafe"`. Сырая память через `*byte`: `Add(p, n)` смещение в байтах, `Alloc(size, drop)` управляемый блок, `Copy(dst, src, n)`, `Addr(p) int64`, `Sizeof(a any) int64`, `TypeOf(a any) *byte` и `DataOf(a any) *byte` (описатель типа и указатель на данные значения в `any`), `MakeAny(data, desc) any`, `CallPtr(f, arg)` вызов функции по указателю, `StringAt`/`StringData`, `BytesAt(p, n)`/`BytesData(b)`.

Загрузка и запись по адресу: `LoadInt`, `LoadInt64`, `LoadFloat`, `LoadChar`, `LoadByte`, `LoadBool`, `LoadString`, `LoadPtr` и `StoreX` для тех же типов. Правило учёта ссылок: загрузка управляемого значения (`string`, указатель) возвращает обычный результат вызова (компилятор сам удерживает и освобождает его), поэтому ячейка памяти сохраняет собственную ссылку; запись удерживает новое значение и освобождает старое, хранившееся в ячейке. Ячейка должна быть инициализирована (нулями или корректным значением).

Временный механизм (будет заменён при самохостинге): `extern fn` с именем `pgt_i_<операция>[_<суффикс>]` компилятор не вызывает как C-функцию, а раскладывает в инструкции (`add`, `load`, `store`, `copy`, `alloc`, `call1`, `desc`, `data`, `mkany`, `ptoi`, `cast`); типы параметров и результата берутся из объявления, для таких функций разрешены параметры типа `any`.

Использование `print`, `println`, `input`, `inputln` без пакета `fmt` — ошибка компиляции: `undefined: println (use fmt.Println from #use "fmt")`.

## Отображения map

Временный синтаксис: он нужен, пока компилятор на C++ не заменён самохостингом. Вся логика (хеш-таблица) написана на PGT в `std/maps`, компилятор только разбирает синтаксис и раскладывает его в вызовы этого пакета.

```pgt
var* ages = make(map[string]int)
ages["bob"] = 30
ages["bob"] += 1
var* sq = map[int]int{1: 1, 2: 4}
var* none map[string]int

ages["bob"]           // 31; отсутствующий ключ даёт нулевое значение
has(ages, "bob")      // true
delete(ages, "bob")   // отсутствующий ключ и nil-отображение допустимы
len(ages)
for k, v in sq { }    // и for k in sq { }
fmt.Println(sq)       // map[1:1 2:4]
```

- Ключ: `int`, `int64`, `uint64`, `char`, `byte`, `bool` или `string`; другой тип ключа — ошибка компиляции. Значение — любой тип.
- Нулевое значение `nil`: чтение возвращает нулевое значение, `len` равна 0, `has` ложно, запись вызывает панику `assignment to entry in nil map`. `m[k].поле = x` запрещено.
- Отображение — ссылочный тип, как массив: присваивание и передача в функцию разделяют одну таблицу. Это управляемый блок со счётчиком ссылок; при освобождении таблица освобождает все ключи и значения.
- Порядок итерации — порядок вставки (детерминированный). Удалённый ключ, вставленный заново, идёт в конец. Вставка во время итерации безопасна для памяти, но порядок обхода после перестройки таблицы не определён.
- `fmt.Println` печатает `map[a:1 b:2]` с ключами по возрастанию, как в Go.
- Хеш: FNV-1a по байтам строки, для чисел множитель с перемешиванием; таблица с открытой адресацией, массив записей в порядке вставки, удаление помечает запись (надгробие), рост и сжатие при заполнении.
- Пакет `std/maps` подключается неявно, как `runtime`: `#use "maps"` не нужен. Выбор сделан ради простоты: синтаксис `map` работает без импорта, а лишний импорт не может стать «неиспользуемым». Компилятор передаёт пакету адреса ключа и значения и дескрипторы типов (`reflect.Type`).
- Самые низкоуровневые функции (`New`, `Get`, `Set`, `Has`, `Delete`, `Len`, `Next`, `KeyAt`, `ValAt`, `KeyType`, `ValType`, `Drop`) принимают сырые указатели и предназначены для компилятора и `fmt`; отдельных `Keys`/`Values` без обобщённых типов сделать нельзя.

## Память

### Автоматическое управление

По умолчанию памятью управляет компилятор: он считает ссылки на каждый объект (reference counting) и сам освобождает память, когда на объект больше никто не ссылается. Вручную ничего вызывать не нужно. Семантика языка при этом не меняется: массивы по-прежнему разделяют данные (`b = a` — тот же массив, как слайсы в Go), строки неизменяемы и разделяются, указатели разделяются.

Что освобождается автоматически:

- строки, созданные во время работы (конкатенация, `str(...)`, `substr`, `upper`, ввод, чтение файлов, результаты функций из `std`);
- данные массивов (литералы, `make`, `append`);
- значения, на которые указывают `new(T)` и `&Struct{...}`;
- локальные переменные, адрес которых взят (`&x`);
- данные внутри интерфейсов;
- структуры, содержащие любое из перечисленного (поле за полем).

Правила (стандартный ARC): значение, которое только что создано (результат вызова, литерал, конкатенация), принадлежит выражению; чтение переменной, поля или элемента ничего не копирует. Когда значение кладётся в переменную, поле, элемент, глобальную переменную, литерал массива или структуры, интерфейс, `append` или возвращается из функции, счётчик увеличивается; при перезаписи старое значение освобождается. Локальные переменные освобождаются при выходе из блока, а также при `return`, `break` и `continue`. Временные значения (`fmt.Println(a + b)`, отброшенный результат вызова) освобождаются в конце оператора. Аргументы функции удерживаются на время вызова, результат функции всегда передаётся вызывающему с владением. Значения глобальных переменных живут до конца программы.

Для каждого типа компилятор генерирует собственные функции удержания и освобождения (поля структуры, элементы массива), поэтому вложенные данные освобождаются вместе с владельцем. Длинные цепочки (связный список из миллионов узлов) освобождаются без рекурсии.

**Ограничения**

- **Циклические ссылки через указатели не освобождаются**: если `a.next = b` и `b.next = a`, счётчики никогда не дойдут до нуля, и память утечёт (структуры вида «двусвязный список», «родитель ↔ потомок»). Для таких структур используйте `var&` и освобождайте их вручную, либо разрывайте цикл (`a.next = nil`) перед выходом из области видимости.
- Указатель на внутреннюю часть объекта (`&s.field`, `&a[i]`) не продлевает жизнь своего родителя: счётчик увеличивает только указатель на начало блока. Не храните такие указатели дольше, чем живёт сам объект.
- Указатели, которые вернули внешние (`extern`) функции из чужого C-кода, и строковые литералы компилятору неизвестны: они считаются бессмертными и не освобождаются. Строки, возвращённые функциями рантайма PGT (`std`), освобождаются как обычные. Если внешняя C-функция сохраняет переданную ей строку или указатель после возврата, она должна сама скопировать данные.
- `free(p)` для указателя из `new` и массива из `make` остаётся рабочим и необязательным: он немедленно освобождает блок и обнуляет переменную `p`. Другие копии этого указателя после `free` недействительны (как и раньше).
- Переменные `var&` (см. ниже) компилятор не отслеживает вообще: он не увеличивает и не уменьшает счётчики для самой переменной и для блока, на который она указывает. Значения, записанные в элементы такого блока (`x[i] = "строка"`), удерживаются и не освобождаются, пока программа работает.

Отладка: переменная окружения `PGT_MEMSTATS=1` заставляет программу в конце вывести в stderr `pgt: live blocks: N` — число ещё не освобождённых блоков (выделено минус освобождено). Для программы без глобальных переменных ожидается `0`; глобальные значения живут до выхода и учитываются.

### Ручное управление: `var&`

Для отдельной переменной автоматическое управление можно отключить: `var&` объявляет переменную, память которой освобождает сам программист. Для этого нужен пакет `memory`:

```pgt
#use "pgt/std/memory"
#use "fmt"

fn main() {
    var& := x = malloc(free[byte] 1024)
    x[0] = 255
    fmt.Println(len(x), " ", x[0], " ", x[1])    // 1024 255 0
    for b in x { /* ... */ }
    free(x)
}
```

Форма записи: `var& := имя = malloc(free[T] N)`. `free[T] N` описывает блок: `N` элементов типа `T`, где `N` — любое целое выражение (`64`, `1024 * 1024`, `memory.MB(1)`). Переменная получает тип `[]T` с `len` = `cap` = `N`; блок заполнен нулями, а индексы, `len(x)` и `for b in x` работают как у обычных массивов, в том числе с проверкой границ.

- Компилятор перестаёт следить за такой переменной: блок живёт, пока его не освободят вызовом `free(x)`. После `free(x)` переменная становится пустым массивом (`len(x) == 0`), поэтому обращение по индексу даёт `panic: index out of range`, а повторный `free(x)` безопасен.
- Переменной `var&` нельзя присваивать (`x = ...` — ошибка компиляции). Элементы менять можно: `x[i] = v`.
- `N < 0` завершает программу с `panic: malloc: negative size`.
- `malloc` допустим только как инициализатор `var&`; `var&` допустим только внутри функций и только с `malloc`. Без `#use "pgt/std/memory"` — ошибка `malloc needs #use "pgt/std/memory"`.
- `free(p)` для указателей из `new` и массивов из `make` работает, но необязателен: см. «Автоматическое управление».

#### Передача существующей переменной

`var*` объявляет переменную, а `var& := имя = malloc(...)` с уже объявленным именем ничего не объявляет: компилятор берёт эту переменную, перестаёт за ней следить и переносит её значение в блок, выделенный вручную. Дальше это забота программиста.

```pgt
#use "fmt"

var* a = 10
var& := a = malloc(free[int] 1)   // a по-прежнему int и равна 10, но живёт в ручной памяти
a = a + 5                          // присваивать можно
fmt.Println(a)                         // 15
free(a)                            // блок освобождён; дальнейшее чтение a — panic: nil pointer dereference
```

- `free[T] N` должен совпадать с типом переменной: для `int` — `free[int] N`, для `[]int` — тоже `free[int] N`.
- `free[byte] N` задаёт размер в байтах: `var& := a = malloc(free[byte] 4)` для `int`. Если байтов меньше, чем нужно типу, программа завершится с `panic: malloc: the block is too small for 'a' (int needs 4 bytes)`.
- Для массива `[]T` блок получает `N` элементов, старые элементы копируются (сколько поместится), а старые данные освобождаются автоматически.
- Передавать можно только в том же блоке, где переменная объявлена (не внутри `if` или цикла), один раз, не константу и не переменную, на которую взят адрес `&`.
- Если имя ещё не объявлено, `var& := x = malloc(free[T] N)` объявляет новую переменную типа `[]T`, как описано выше.

Тип `byte` — беззнаковое 8-битное целое (`0..255`): арифметика и сравнения беззнаковые, переполнение переходит по кругу (`byte(250) + 10 == 4`). `fmt.Println` печатает его числом, а `[]byte` — как `[1 2 3]`. Преобразования: `byte(x)`, `int(b)`, `float(b)`.

Пути `"pgt/std/memory"`, `"std/memory"` и `"memory"` указывают на один и тот же пакет; в коде он называется `memory`.

Выделение и освобождение для `var&` реализованы не в компиляторе, а в стандартной библиотеке: `var& := x = malloc(free[T] N)` превращается в вызов внутренней функции `memory.alloc(N, sizeof(T))`, а `free(x)` — в `memory.release(...)`. Они проверяют размер (`panic: malloc: negative size`, `panic: malloc: size overflow`), выделяют обнулённую память через `calloc` (при нехватке — `panic: out of memory`) и ведут статистику. Компилятору остаются только разбор синтаксиса, проверка импорта, размер `T` и превращение блока в `[]T`.

Для такой работы в язык добавлены два низкоуровневых примитива: `unsafeData(a []T) *T` возвращает указатель на данные массива, `unsafeSlice(p *T, n int64) []T` оборачивает блок памяти в массив длиной и ёмкостью n без учёта ссылок.

API пакета `memory`:

| Функция | Описание |
|---|---|
| `Malloc(n int) []byte` | Новый обнулённый блок из n байт |
| `Free(buf []byte)` | Освобождает блок из `Malloc`/`Realloc`/`Grow` |
| `Realloc(buf []byte, n int) []byte` | Меняет размер блока, сохраняя данные |
| `Grow(buf []byte, extra int) []byte` | Увеличивает блок на extra байт |
| `Copy(dst, src []byte) int` | Копирует min(len) байт, возвращает их число |
| `Set(buf []byte, v byte)` / `Zero(buf []byte)` | Заполняет буфер значением / нулями |
| `Fill(buf, pattern []byte)` | Заполняет буфер повторяющимся шаблоном |
| `Compare(a, b []byte) int` / `Equal(a, b []byte) bool` | Сравнение: -1, 0, 1 / равенство |
| `Live() int` / `LiveBytes() int64` | Число и суммарный размер живых ручных блоков |
| `KB(n int) int`, `MB(n int) int`, `GB(n int) int64` | Размеры в байтах |

```pgt
#use "fmt"

var& := x = malloc(free[int] 4)
fmt.Println(memory.Live(), " ", memory.LiveBytes())   // 1 16
free(x)
fmt.Println(memory.Live())                           // 0
```

### panic и ошибки времени выполнения

Как и в Go, `panic` распознаёт компилятор, но реализован он на PGT в пакете `std/runtime` (`runtime.pgt`). Пакет `runtime` загружается в каждую программу неявно, без `#use`. Компилятор превращает `panic(msg)` и свои проверки в вызовы его закрытых функций: `panicString` (`panic: <msg>` в stderr после сброса stdout, код выхода 2), `panicIndex`, `panicSlice`, `panicSliceCap`, `panicNil`, `panicDiv`. Пользовательские функции и переменные с такими именами им не мешают, потому что имена принадлежат пакету. Внутренние ошибки C-рантайма (например, `out of memory`) тоже идут через `runtime.panicString`.

## Внешние функции (C)

`extern fn` объявляет функцию из C-библиотеки или из рантайма PGT и позволяет её вызывать:

```pgt
extern fn atan2(y float, x float) float
extern fn getenv(name string) string
```

Типы передаются так: `int` — `int32_t`, `int64` — `int64_t`, `uint64` — `uint64_t`, `float` — `double`, `char` — `char`, `byte` — `uint8_t`, `bool` — `bool`, `string` — `const char*`, `*T` — указатель, `[]T` — указатель на `{data, len, cap, base}` (только как параметр). Структуры и интерфейсы передавать нельзя. Внешние функции из `libc` и `libm` доступны сразу; на них построена стандартная библиотека.

# Стандартная библиотека

Пакеты стандартной библиотеки подключаются по имени, без `pgt.mod`:

```pgt
#use (

#use "fmt"

fn main() {
    fmt.Println(strings.Join(strings.Split("a,b,c", ","), " | "))
```

| `syscall/purec-os` | пакет `syscall_purec_os`: номера системных вызовов PureC OS (`SYS_WRITE`, `SYS_FORK`, `SYS_DRAW_RECT`, `SYS_FILE_OPEN`, ...) |

Полный список функций — в [std/README.md](std/README.md); исходники лежат в `std/` и написаны на самом PGT.

Неиспользуемый импорт — ошибка, как в Go: каждый пакет из `#use` должен встречаться в файле как `имя.Что-то` (вызов, константа, тип). Для `memory` использованием также считается `var& := x = malloc(...)`.

```pgt
#use (
    "math"
    "strings"   // ошибка: "strings" imported and not used
)
```

## Ассемблер std/asm

Пакет `std/asm` (`#use "asm"`) — ассемблер x86-64 в синтаксисе Intel, написанный на PGT. Он превращает текст в машинный код: `asm.Assemble(src)` возвращает `Result{Code, Err, Line}`, `asm.MustAssemble(src)` паникует с сообщением `asm: line N: ...`, `asm.Hex(code)` печатает байты, `asm.Load(code)` кладёт код в исполняемую память (`mmap` + `mprotect`), `f.Call(a, b, ...)` вызывает его с целыми аргументами, `asm.Free(f)` освобождает память.

```pgt
#use "asm"
#use "fmt"

var* f = asm.Load(asm.MustAssemble("lea rax, [rdi + rsi*2]\nret"))
fmt.Println(f.Call(1, 10))
asm.Free(f)
```

Подробности синтаксиса и список инструкций — в [std/README.md](std/README.md). Блок `asm { }` внутри самого языка описан в разделе «Ассемблерные вставки».

## Ассемблерные вставки

Внутри функции можно написать блок на ассемблере x86-64 (синтаксис Intel). Нужен импорт `#use "asm"` (или `"pgt/std/asm"`), без него: `asm block needs #use "pgt/std/asm"`.

```pgt
#use "asm"

var* x = 5
var* y = 0
asm {
    mov eax, {x}
    add eax, 10
    mov {y}, eax
}
```

Правила:

- Текст блока берётся как есть до закрывающей `}`; номера строк сохраняются. `{имя}` — подстановка переменной, любая другая `{` внутри блока — ошибка. Комментарии ассемблера начинаются с `;` (скобки в них не разбираются). Блок без закрывающей `}` — ошибка `unterminated asm block`.
- Переменная в `{имя}` должна быть видимой локальной или глобальной и иметь тип `int`, `int64`, `byte`, `char`, `bool` или указатель `*T`; иначе ошибка компиляции с именем переменной и допустимыми типами. Константы запрещены (запись в них не обнаружить). Неопределённое имя — ошибка. Переданные в `var&` переменные работают по текущему адресу.
- Каждая переменная получает 8-байтовый слот. `{x}` превращается в операнд памяти нужного размера: `dword [r15 + 8*i]` для `int`, `qword [...]` для `int64` и указателей, `byte [...]` для `byte`, `char`, `bool`. Перед блоком значения копируются в слоты (остальные байты слота нули), после блока копируются обратно с усечением до размера типа. Запись через указатель: `mov rax, {p}` и `mov qword [rax], 42`.
- `r15` (и `r15d`, `r15w`, `r15b`) зарезервирован для доступа к переменным: `r15 is reserved inside asm blocks for variable access`. Инструкции `ret` и `leave` в блоке запрещены.
- Регистры `rbx`, `rbp`, `r12`-`r15` сохраняются и восстанавливаются автоматически (пролог и эпилог блока), остальные можно портить свободно. Метки внутри блока локальны для блока.
- Блок ассемблируется при первом выполнении и кешируется (один кеш на блок), следующие выполнения только вызывают готовый код. Реализация целиком в `std/asm` (`RunBlock`), компилятор лишь собирает таблицу слотов и копирует значения туда и обратно.
- Ошибки блока (синтаксис ассемблера, `r15`, `ret`) пока возникают во время выполнения как паника `asm block at ФАЙЛ:СТРОКА: line N: сообщение`, где `СТРОКА` — строка с `asm {`, а `N` — реальная строка в исходнике. После самохостинга они станут ошибками компиляции. Проверить текст без запуска можно через `asm.CheckBlock(text, names, sizes) Result` (`names` — имена переменных, `sizes` — их размеры 1, 4 или 8).

# Компилятор

```
pgt build [dir|file.pgt] [-o out]   скомпилировать программу
pgt run [dir|file.pgt] [-- args]    скомпилировать, запустить и удалить исполняемый файл
pgt new <name> [-t template]        создать проект
pgt build file.pgt --debug          показать токены и синтаксическое дерево, затем собрать
pgt build - --debug=json < file     то же в JSON без сборки (для PGT Studio; '-' — читать stdin)
pgt build . --debug=project         JSON всего проекта: файлы, импорты, вес в токенах, AST (для PGT Studio)
```

`--debug` печатает для каждого файла пакета все токены с позицией (`строка:столбец`), видом и текстом, а затем дерево разбора:

```
-- syntax tree
Program package main (1:1)
├─ Function fn main() (3:1)
│  └─ ForIn for i in (4:5)
│     ├─ Part from (4:14)
│     │  └─ IntLit 0 (4:14)
...
```

Синтаксическая ошибка не мешает: печатаются токены, прочитанные до неё, и сама ошибка.

Тесты компилятора: `tests/run.sh` (или `ctest` в папке сборки).
