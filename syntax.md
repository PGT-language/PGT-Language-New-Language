# Расширения языка

## Типы

`int` (32 бита), `int64`, `float`, `char`, `byte` (беззнаковый 8-битный), `string`, `bool`, `void`, а также составные: `[]T` (массив), `*T` (указатель), имя структуры или интерфейса.

```pgt
var* a = 1                  // int
var* b int64 = 3000000000
var* c = 'x'                // char
var* d + {float} = 2        // явный тип
var* e int                  // нулевое значение
```

Преобразования: `int(x)`, `int64(x)`, `float(x)`, `char(x)`, `byte(x)`, `bool(x)`, `string(x)`.

Целые литералы можно писать в шестнадцатеричном и двоичном виде: `0xFF`, `0b1010`. Комментарии: `// до конца строки` и `/* блочные */`.

## Константы и глобальные переменные

```pgt
const PI = 3.14
const (
    Answer = 42
    Name = "PGT"
    Big int64 = 9000000000
)

var* counter = 0
var* table = buildTable()   // любое выражение, в том числе вызов функции
```

Константы и глобальные переменные объявляются только на верхнем уровне файла. Они инициализируются до вызова `main`: сначала в импортированных пакетах, затем в порядке объявления. Константу нельзя изменить: `PI = 3` — ошибка компиляции. Из другого пакета они доступны как `math.Pi` (если имя с большой буквы).

## Операторы

Арифметика `+ - * / %`, сравнение `== != < > <= >=`, логика `&& || !` (с короткой оценкой), побитовые `& | ^ << >> ~`, составное присваивание `+= -= *= /= %=`, `++` и `--` для любых изменяемых значений (`arr[i]++`, `p.X--`, `*p++`).

Строки склеиваются через `+`, в том числе с числами, символами и bool: `"n=" + 5`. Строки сравниваются операторами `== != < > <= >=` (лексикографически).

Приоритеты (от слабого к сильному), как в Go:

| Уровень | Операторы |
|---|---|
| 1 | `\|\|` |
| 2 | `&&` |
| 3 | `== != < > <= >=` |
| 4 | `+ - \| ^` |
| 5 | `* / % << >> &` |
| 6 | унарные `- ! ~ * &` |

Поэтому `x & 1 == 1` означает `(x & 1) == 1`.

Целочисленное деление на ноль завершает программу с `panic: integer divide by zero`.

## Перенос строк

Точка с запятой не нужна: оператор заканчивается вместе со строкой. Если выражение продолжается на следующей строке, оставьте оператор в конце строки:

```pgt
var* total = a +
    b +
    c
```

Строка, начинающаяся с `*`, `&`, `-`, `(` или `[`, — это новый оператор, а не продолжение предыдущего (`var* p = &x` и следующей строкой `*p = 5` — два разных оператора).

## Условия и циклы

```pgt
if x < 0 {
} else if x == 0 {
} else {
}

for var* i = 0; i < 10; i++ { }
for i in 0..10 { }          // 0..9
for x in arr { }
for i, x in arr { }
for ch in "text" { }
for cond { }
for { break }

switch x {
    case 1, 2 { }
    case 3 { }
    default { }
}
```

`switch` без значения проверяет условия по порядку:

```pgt
switch {
    case x < 0 { println("negative") }
    case x == 0 { println("zero") }
    default { println("positive") }
}
```

`case` сравнивает значения любых типов, у которых есть `==` (числа, символы, строки, bool). Выполняется первая подходящая ветка; перехода в следующую нет.

`break` и `continue` работают во всех циклах, `break` — и в `switch`.

## Массивы

```pgt
var* arr = [1, 2, 3]
arr[0] = 10
arr = append(arr, 4, 5)
println(len(arr), arr)
var* grid = make([]int, 5)
var* names + {[]string} = []
```

Выход за границы массива завершает программу с сообщением `panic: index out of range`.

Массив хранит ссылку на свои данные, как срез в Go: `var* b = a` и передача массива в функцию не копируют элементы, поэтому `b[0] = 1` меняет и `a`. `append` может перенести данные в новую память, поэтому всегда присваивайте результат: `a = append(a, x)`. Массивы можно вкладывать: `[][]int`, `[]Point`, `[]*Node`.

`println` печатает массивы и структуры целиком: `[1 2 3]`, `{1 2}`, указатель на структуру — `&{1 2}`, пустой указатель — `<nil>`.

## Структуры и методы

```pgt
struct Point {
    X int
    Y int
}

fn (p Point) Sum() int {        // получатель по значению
    return p.X + p.Y
}

fn (p *Point) Move(dx int) {    // получатель по указателю
    p.X += dx
}

var* p = Point{X: 1, Y: 2}
p.Move(5)
println(p, p.Sum())
```

## Указатели

```pgt
var* x = 1
var* px = &x
*px = 5
var* q = &Point{X: 1}
var* h = new(Point)
free(h)
```

`nil` — пустой указатель, строка, массив или интерфейс. Разыменование `nil` завершает программу с `panic: nil pointer dereference`.

На локальную переменную можно взять указатель и вернуть его из функции: такие переменные автоматически размещаются в куче.

Методы с получателем по указателю можно вызывать у обычной переменной (`p.Move(5)`), а методы по значению — у указателя (`ptr.Sum()`): адрес берётся и снимается автоматически. Поля доступны через указатель так же: `ptr.X`.

## Интерфейсы

Реализуются неявно, как в Go: достаточно, чтобы у типа были все методы.

```pgt
interface Shape {
    Area() float
}

fn describe(s Shape) {
    println(s.Area())
}

describe(Rect{W: 2, H: 3})     // методы по значению: подходит и Rect, и *Rect
describe(&Circle{R: 1})        // методы по указателю: подходит только *Circle
```

Переменная-интерфейс без значения равна `nil`; вызов метода у неё завершает программу с паникой. Пустой интерфейс `interface Any {}` принимает значение любого типа. `println` печатает значение, лежащее внутри интерфейса.

## Функции с типами

```pgt
fn add(a int, b int) int {
    return a + b
}

fn greet(name string) {
    println("Hello, " + name)
}
```

Параметры без типа считаются `int`. Функция без типа результата возвращает `int`, если в ней есть `return` со значением, иначе ничего.

## Ввод

```pgt
input("Число: ", n)        // int, int64, float, char, bool, string (одно слово)
inputln("Строка: ", line)  // строка целиком
input(p.X)                 // можно читать в поле структуры или элемент массива
```

Если прочитать значение не удалось (конец ввода или не число), переменная не меняется. `bool` принимает `true/false`, `yes/no`, `y/n`, `1/0`.

## Память

### Автоматическое управление

По умолчанию памятью управляет компилятор: он считает ссылки на каждый объект (reference counting) и сам освобождает память, когда на объект больше никто не ссылается. Вручную ничего вызывать не нужно. Семантика языка при этом не меняется: массивы по-прежнему разделяют данные (`b = a` — тот же массив, как слайсы в Go), строки неизменяемы и разделяются, указатели разделяются.

Что освобождается автоматически:

- строки, созданные во время работы (конкатенация, `str(...)`, `substr`, `upper`, ввод, чтение файлов, результаты функций из `std`);
- данные массивов (литералы, `make`, `append`);
- значения, на которые указывают `new(T)` и `&Struct{...}`;
- локальные переменные, адрес которых взят (`&x`);
- данные внутри интерфейсов;
- структуры, содержащие любое из перечисленного (поле за полем).

Правила (стандартный ARC): значение, которое только что создано (результат вызова, литерал, конкатенация), принадлежит выражению; чтение переменной, поля или элемента ничего не копирует. Когда значение кладётся в переменную, поле, элемент, глобальную переменную, литерал массива или структуры, интерфейс, `append` или возвращается из функции, счётчик увеличивается; при перезаписи старое значение освобождается. Локальные переменные освобождаются при выходе из блока, а также при `return`, `break` и `continue`. Временные значения (`println(a + b)`, отброшенный результат вызова) освобождаются в конце оператора. Аргументы функции удерживаются на время вызова, результат функции всегда передаётся вызывающему с владением. Значения глобальных переменных живут до конца программы.

Для каждого типа компилятор генерирует собственные функции удержания и освобождения (поля структуры, элементы массива), поэтому вложенные данные освобождаются вместе с владельцем. Длинные цепочки (связный список из миллионов узлов) освобождаются без рекурсии.

**Ограничения**

- **Циклические ссылки через указатели не освобождаются**: если `a.next = b` и `b.next = a`, счётчики никогда не дойдут до нуля, и память утечёт (структуры вида «двусвязный список», «родитель ↔ потомок»). Для таких структур используйте `var&` и освобождайте их вручную, либо разрывайте цикл (`a.next = nil`) перед выходом из области видимости.
- Указатель на внутреннюю часть объекта (`&s.field`, `&a[i]`) не продлевает жизнь своего родителя: счётчик увеличивает только указатель на начало блока. Не храните такие указатели дольше, чем живёт сам объект.
- Указатели, которые вернули внешние (`extern`) функции из чужого C-кода, и строковые литералы компилятору неизвестны: они считаются бессмертными и не освобождаются. Строки, возвращённые функциями рантайма PGT (`std`), освобождаются как обычные. Если внешняя C-функция сохраняет переданную ей строку или указатель после возврата, она должна сама скопировать данные.
- `free(p)` для указателя из `new` и массива из `make` остаётся рабочим и необязательным: он немедленно освобождает блок и обнуляет переменную `p`. Другие копии этого указателя после `free` недействительны (как и раньше).
- Переменные `var&` (см. ниже) компилятор не отслеживает вообще: он не увеличивает и не уменьшает счётчики для самой переменной и для блока, на который она указывает. Значения, записанные в элементы такого блока (`x[i] = "строка"`), удерживаются и не освобождаются, пока программа работает.

Отладка: переменная окружения `PGT_MEMSTATS=1` заставляет программу в конце вывести в stderr `pgt: live blocks: N` — число ещё не освобождённых блоков (выделено минус освобождено). Для программы без глобальных переменных ожидается `0`; глобальные значения живут до выхода и учитываются.

### Ручное управление: `var&`

Для отдельной переменной автоматическое управление можно отключить: `var&` объявляет переменную, память которой освобождает сам программист. Для этого нужен пакет `memory`:

```pgt
#use "pgt/std/memory"

fn main() {
    var& := x = malloc(free[byte] 1024)
    x[0] = 255
    println(len(x), " ", x[0], " ", x[1])    // 1024 255 0
    for b in x { /* ... */ }
    free(x)
}
```

Форма записи: `var& := имя = malloc(free[T] N)`. `free[T] N` описывает блок: `N` элементов типа `T`, где `N` — любое целое выражение (`64`, `1024 * 1024`, `memory.MB(1)`). Переменная получает тип `[]T` с `len` = `cap` = `N`; блок заполнен нулями, а индексы, `len(x)` и `for b in x` работают как у обычных массивов, в том числе с проверкой границ.

- Компилятор перестаёт следить за такой переменной: блок живёт, пока его не освободят вызовом `free(x)`. После `free(x)` переменная становится пустым массивом (`len(x) == 0`), поэтому обращение по индексу даёт `panic: index out of range`, а повторный `free(x)` безопасен.
- Переменной `var&` нельзя присваивать (`x = ...` — ошибка компиляции). Элементы менять можно: `x[i] = v`.
- `N < 0` завершает программу с `panic: malloc: negative size`.
- `malloc` допустим только как инициализатор `var&`; `var&` допустим только внутри функций и только с `malloc`. Без `#use "pgt/std/memory"` — ошибка `malloc needs #use "pgt/std/memory"`.
- `free(p)` для указателей из `new` и массивов из `make` работает, но необязателен: см. «Автоматическое управление».

Тип `byte` — беззнаковое 8-битное целое (`0..255`): арифметика и сравнения беззнаковые, переполнение переходит по кругу (`byte(250) + 10 == 4`). `println` печатает его числом, а `[]byte` — как `[1 2 3]`. Преобразования: `byte(x)`, `int(b)`, `float(b)`.

Пути `"pgt/std/memory"`, `"std/memory"` и `"memory"` указывают на один и тот же пакет; в коде он называется `memory`.

Выделение и освобождение для `var&` реализованы не в компиляторе, а в стандартной библиотеке: `var& := x = malloc(free[T] N)` превращается в вызов внутренней функции `memory.alloc(N, sizeof(T))`, а `free(x)` — в `memory.release(...)`. Они проверяют размер (`panic: malloc: negative size`, `panic: malloc: size overflow`), выделяют обнулённую память через `calloc` (при нехватке — `panic: out of memory`) и ведут статистику. Компилятору остаются только разбор синтаксиса, проверка импорта, размер `T` и превращение блока в `[]T`.

Для такой работы в язык добавлены два низкоуровневых примитива: `unsafeData(a []T) *T` возвращает указатель на данные массива, `unsafeSlice(p *T, n int64) []T` оборачивает блок памяти в массив длиной и ёмкостью n без учёта ссылок.

API пакета `memory`:

| Функция | Описание |
|---|---|
| `Malloc(n int) []byte` | Новый обнулённый блок из n байт |
| `Free(buf []byte)` | Освобождает блок из `Malloc`/`Realloc`/`Grow` |
| `Realloc(buf []byte, n int) []byte` | Меняет размер блока, сохраняя данные |
| `Grow(buf []byte, extra int) []byte` | Увеличивает блок на extra байт |
| `Copy(dst, src []byte) int` | Копирует min(len) байт, возвращает их число |
| `Set(buf []byte, v byte)` / `Zero(buf []byte)` | Заполняет буфер значением / нулями |
| `Fill(buf, pattern []byte)` | Заполняет буфер повторяющимся шаблоном |
| `Compare(a, b []byte) int` / `Equal(a, b []byte) bool` | Сравнение: -1, 0, 1 / равенство |
| `Live() int` / `LiveBytes() int64` | Число и суммарный размер живых ручных блоков |
| `KB(n int) int`, `MB(n int) int`, `GB(n int) int64` | Размеры в байтах |

```pgt
var& := x = malloc(free[int] 4)
println(memory.Live(), " ", memory.LiveBytes())   // 1 16
free(x)
println(memory.Live())                           // 0
```

## Встроенные функции

| Функция | Описание |
|---|---|
| `len(x)` | длина массива или строки |
| `append(a, v...)` | добавить элементы в массив |
| `make([]T, n)`, `new(T)`, `free(p)` | выделение и освобождение памяти |
| `malloc(free[T] n)` | блок памяти для `var&` (только как инициализатор, см. «Память») |
| `str(x)`, `parseInt(s)`, `parseInt64(s)`, `parseFloat(s)` | преобразование строк |
| `chars(s)` → `[]char`, `string(chars)` → `string` | строка как массив символов |
| `substr(s, from, n)`, `contains`, `indexOf`, `startsWith`, `endsWith`, `upper`, `lower` | строки |
| `abs`, `min`, `max` | для `int`, `int64` и `float` (`min`/`max` — и для строк) |
| `sqrt`, `pow`, `floor`, `ceil`, `round`, `trunc`, `sin`, `cos`, `tan`, `log`, `exp` | математика, результат `float` |
| `readFile(path)`, `writeFile(path, s)`, `appendFile(path, s)`, `fileExists(path)` | файлы |
| `rand()`, `srand(n)`, `exit(code)`, `panic(msg)` | прочее |

Собственная функция пакета с тем же именем заменяет встроенную (например, своя `min`).

Все встроенные функции описаны в `std/builtin/builtin.pgt`. Это файл только для документации: он не компилируется, и `#use "builtin"` даёт ошибку.

### panic и ошибки времени выполнения

Как и в Go, `panic` распознаёт компилятор, но реализован он на PGT в пакете `std/runtime` (`runtime.pgt`). Пакет `runtime` загружается в каждую программу неявно, без `#use`. Компилятор превращает `panic(msg)` и свои проверки в вызовы его закрытых функций: `panicString` (`panic: <msg>` в stderr после сброса stdout, код выхода 2), `panicIndex`, `panicNil`, `panicDiv`. Пользовательские функции и переменные с такими именами им не мешают, потому что имена принадлежат пакету. Внутренние ошибки C-рантайма (например, `out of memory`) тоже идут через `runtime.panicString`.

## Внешние функции (C)

`extern fn` объявляет функцию из C-библиотеки или из рантайма PGT и позволяет её вызывать:

```pgt
extern fn atan2(y float, x float) float
extern fn getenv(name string) string
```

Типы передаются так: `int` — `int32_t`, `int64` — `int64_t`, `float` — `double`, `char` — `char`, `byte` — `uint8_t`, `bool` — `bool`, `string` — `const char*`, `*T` — указатель, `[]T` — указатель на `{data, len, cap}` (только как параметр). Структуры и интерфейсы передавать нельзя. Внешние функции из `libc` и `libm` доступны сразу; на них построена стандартная библиотека.

# Стандартная библиотека

Пакеты стандартной библиотеки подключаются по имени, без `pgt.mod`:

```pgt
#use (
    "strings"
    "math"
)

fn main() {
    println(strings.Join(strings.Split("a,b,c", ","), " | "))
    println(math.Hypot(3, 4))
}
```

| Пакет | Что внутри |
|---|---|
| `strings` | поиск, замена, обрезка, разбиение и склейка, выравнивание, проверки символов, `Builder` |
| `math` | константы (`Pi`, `E`, `MaxInt`, ...), тригонометрия, логарифмы, `Gcd`, `Lcm`, `IsPrime`, `Factorial`, `Fib`, `PowInt` |
| `arrays` | сумма, минимум, поиск, сортировка, бинарный поиск, `Range`, `Unique` для `[]int`, `[]float`, `[]string` |
| `conv` | числа ⇄ строки: `Itoa`, `Atoi`, `IsInt`, `FormatFloat`, `FormatInt` в любой системе счисления |
| `io` | построчное чтение stdin: `ReadLine`, `EOF`, `ReadLines`, `Prompt` |
| `os` | аргументы командной строки, переменные окружения, файлы, запуск команд |
| `time` | текущее время, паузы, форматирование дат, `Stopwatch` |
| `memory` | блоки памяти: `Copy`, `Set`, `Zero`, `KB`, `MB` (для `var&` и `malloc`) |
| `rand` | случайные числа: `Int`, `IntN`, `Range`, `Float`, `Shuffle`, `Pick`, воспроизводимый `Seed` |

Полный список функций — в [std/README.md](std/README.md); исходники лежат в `std/` и написаны на самом PGT.

# Компилятор

```
pgt build [dir|file.pgt] [-o out]   скомпилировать программу
pgt run [dir|file.pgt] [-- args]    скомпилировать, запустить и удалить исполняемый файл
pgt new <name> [-t template]        создать проект
pgt build file.pgt --debug          показать токены и синтаксическое дерево, затем собрать
pgt build - --debug=json < file     то же в JSON без сборки (для PGT Studio; '-' — читать stdin)
pgt build . --debug=project         JSON всего проекта: файлы, импорты, вес в токенах, AST (для PGT Studio)
```

`--debug` печатает для каждого файла пакета все токены с позицией (`строка:столбец`), видом и текстом, а затем дерево разбора:

```
-- syntax tree
Program package main (1:1)
├─ Function fn main() (3:1)
│  └─ ForIn for i in (4:5)
│     ├─ Part from (4:14)
│     │  └─ IntLit 0 (4:14)
...
```

Синтаксическая ошибка не мешает: печатаются токены, прочитанные до неё, и сама ошибка.

Тесты компилятора: `tests/run.sh` (или `ctest` в папке сборки).
